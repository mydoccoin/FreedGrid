# FreedGrid

Мобильное приложение (PWA + Android APK) для комьюнити Формулы-1: смотреть трансляцию, общаться в общем чате и голосовом эфире, находить офлайн-встречи в кино.

Сделано по макету Figma (10 экранов). Работает в браузере на телефоне и на компьютере, устанавливается на домашний экран как приложение. Собирается в APK через Capacitor без переписывания кода.

Данные хранятся на общем сервере **Supabase**: аккаунты, чат, объявления, билеты, баны и галочки видны на всех устройствах.

## 1. Подключение сервера (один раз)

### 1.1. Создай проект Supabase

1. Зарегистрируйся на https://supabase.com и создай новый проект (бесплатного тарифа хватает).
2. Дождись, пока база запустится.
3. Открой **Project Settings → API** и скопируй:
   - **Project URL** — вида `https://xxxx.supabase.co`;
   - **anon public key** — длинный ключ `eyJ...`.
4. Открой **SQL Editor → New query**, вставь содержимое файла [`supabase/schema.sql`](supabase/schema.sql) целиком и нажми **Run**.

Скрипт создаёт таблицы, правила доступа (RLS), realtime-подписки и функции для админа. Его можно запускать повторно — он ничего не сломает.

> Если база уже была создана раньше, выполни ещё три файла:
> `supabase/migrations/20261022_favorites.sql` — поля любимой команды и пилота;
> `supabase/migrations/20261023_broadcasts.sql` — ссылки на трансляции из админки;
> `supabase/migrations/20261024_social_payments_skypro.sql` — посты, комментарии, лайки, личные сообщения, оплата ЮMoney и обязательное одобрение объявлений.
> Без последнего файла новые разделы ленты/сообщений и оплата не заработают, а объявления останутся видимыми без проверки.

### 1.2. Включи подтверждение email, SMTP и ссылки возврата

1. **Authentication → Sign In / Providers → Email** → включи **Confirm email**.
   Тогда после регистрации Supabase отправит письмо, а вход будет доступен только после перехода по ссылке.
   Если подтверждение не нужно — выключи его, и приложение сразу создаст сессию.

2. **Authentication → URL Configuration**:
   - **Site URL** — адрес опубликованного сайта, например `https://freedgrid.netlify.app`;
   - **Redirect URLs** — добавь:
     - `https://freedgrid.netlify.app/**` (свой домен);
     - `http://localhost:5173/**` для разработки;
     - `app.freedgrid.mobile://auth` для Android APK.

3. **Authentication → SMTP Settings** — подключи свой SMTP (Resend, Brevo, Mailgun, Gmail с app password).
   Встроенная почта Supabase подходит только для теста: у неё жёсткие лимиты, и письма часто попадают в спам.

> Если в `.env` задан `VITE_SITE_URL`, ссылки из писем всегда открывают сайт.
> Если он пустой, сайт использует свой текущий адрес, а Android APK — схему `app.freedgrid.mobile://auth` и открывает приложение.
> Схему `app.freedgrid.mobile://auth` обязательно добавь в Redirect URLs, иначе Supabase не отправит письмо.

> **Сброс пароля временно отключён.** Ссылка «забыл пароль» убрана со экрана входа. Экран `/reset-password` оставлен для старых ссылок из писем.

### 1.3. Пропиши ключи в `.env`

Создай в корне проекта файл `.env` (образец — `.env.example`):

```env
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...

# Необязательно: публичный адрес сайта для ссылок из писем.
# Если не задан, Android открывает приложение через app.freedgrid.mobile://auth.
# VITE_SITE_URL=https://freedgrid.netlify.app
```

`anon key` — публичный ключ, он и так попадает в собранный сайт/APK. Пароли пользователей и `service_role` в приложении не хранятся.

Для голосового чата в мобильных сетях желателен TURN-сервер (необязательно):

```env
VITE_TURN_URL=turn:your-turn-host:3478
VITE_TURN_USERNAME=user
VITE_TURN_CREDENTIAL=secret
```

Без TURN используется бесплатный STUN Google — этого хватает в большинстве домашних Wi-Fi, но часть мобильных операторов может не соединиться.

### 1.4. Пересобери приложение

```bash
npm install
npm run build
npm run preview
```

Если `.env` нет, приложение покажет экран «Общий сервер не настроен» и не будет пытаться ходить в сеть.

**Первый зарегистрировавшийся пользователь становится администратором.** В его профиле появляется кнопка «админ-панель».

### 1.5. Оплата ЮMoney и билеты

1. Выполни миграцию `supabase/migrations/20261024_social_payments_skypro.sql` в **SQL Editor**.
2. Зайди в приложение под админом → **админ-панель → оплата**.
3. Укажи номер кошелька **ЮMoney** и сохрани. Можно также задать `VITE_YOOMONEY_WALLET` в `.env` как запасной вариант.

Логика оплаты: платный билет создаётся со статусом `awaiting_payment`, открывается страница ЮMoney; после оплаты пользователь нажимает «я оплатил» → `pending_review`; админ сверяет label в ЮMoney и нажимает «подтвердить оплату» → `paid`.

> Email-отправка билетов временно отключена. Купленный билет отображается в личном профиле пользователя. Функция `send-ticket` остаётся в проекте, но приложение её сейчас не вызывает.

## 3. Android APK

APK собирается из той же папки `dist`, поэтому веб-версия и приложение не расходятся: изменил код → `npm run build` → `cap sync` → новая сборка.

```bash
npm run build
npx cap sync android
cd android
gradlew.bat assembleDebug
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.

Что нужно на машине:

- **JDK 21** (Capacitor 8 не собирается на Java 8);
- **Android SDK**: `platforms;android-36`, `build-tools;36.0.0`, `platform-tools`;
- путь к SDK — в `android/local.properties` (`sdk.dir=...`), JDK — через `JAVA_HOME`.

На этом компьютере инструменты лежат на диске `F:` (`F:\android\jdk21`, `F:\android\sdk`), потому что на `C:` мало места, а кеш Gradle вынесен в `F:\android\gradle-home`.

APK подписан debug-ключом — этого достаточно, чтобы установить его на телефон вручную (Android попросит разрешить установку из неизвестных источников). Для Google Play нужен отдельный release-ключ и `bundleRelease`.

> В APK попадает `anon key` из `.env` на момент сборки. Сменил проект Supabase — пересобери APK и переустанови.

### 3.1. Виджеты на домашний экран

В APK есть два виджета:

- **FreedGrid — следующий ГП** — название этапа, город, дата и живой отсчёт до старта;
- **FreedGrid — моя команда** — любимая команда, пилот и число их болельщиков.

Добавляются как обычные Android-виджеты: долгое нажатие на свободном месте рабочего стола → «Виджеты» → FreedGrid. Данные обновляются, когда приложение открыто или когда меняется профиль. Если виджет показывает «открой приложение», запусти FreedGrid один раз после установки.

## 5. Как устроен сервер

### Таблицы

- `profiles` — username, имя, аватар, цвет, любимая команда/пилот, флаги `is_admin`, `is_verified`, `is_banned`.
- `private_emails` — email отдельно от профиля. Публично не читается, доступен только админу через `admin_list_emails()`.
- `events` — объявления о встречах и статус проверки (`ok / review / blocked`).
- `messages` — общий чат.
- `tickets` — кто купил билет на какое мероприятие.
- `ai_settings` — настройки ИИ-модерации (ключ, модель, адрес API). Читаются только админом.

Email пользователя не хранится в `profiles`, поэтому не утекает даже через realtime-подписки.

### Правила доступа (RLS)

- Читать профили, объявления (кроме заблокированных) и чат может любой, включая гостя.
- Писать в чат, создавать объявления и покупать билеты — только вошедший и не забаненный.
- Менять свой профиль можно только самому (`name`, `username`, `avatar`, `bio`, `favorite_team`, `favorite_driver`).
- Баны, галочки и модерация объявлений — только через `SECURITY DEFINER`-функции, которые проверяют `is_admin()`.
- Первый зарегистрировавшийся получает `is_admin` через триггер на `auth.users`.

### Realtime

Изменения `profiles`, `events`, `messages` и `tickets` приходят на все открытые устройства через Supabase Realtime. После бана или выдачи галочки обновление видно без перезагрузки.

### Голос

Голосовой чат — настоящий WebRTC (mesh): каждый участник соединяется с каждым напрямую, звук идёт минуя сервер.

- Сигналинг (offer/answer/ICE) и список участников — через Supabase Realtime (broadcast + presence).
- STUN — Google. TURN — через `VITE_TURN_*`, если задан.
- Кнопка «выключить микрофон» отключает локальный трек и показывает это остальным.
- Индикатор речи считается по громкости через Web Audio API.
- Ограничение mesh: комфортно до ~6–8 человек. Для больших комнат нужен SFU (LiveKit и т.п.).

## 6. Календарь и трансляции

Календарь лежит в `src/lib/season.ts` — этапы 15–23 сезона 2026 с реальными датами.

- **Таймер** на главной считает до ближайшей гонки (`getNextRace`).
- **Город на обложке** — тоже следующий этап, дата берётся из календаря.
- **Плеер** на экране Race показывает запись канала [STANIZLAVSKY](https://rutube.ru/video/person/35504962/) на Rutube. Переключатели появляются для тех сессий, у которых есть ссылка: три практики, спринт-квалификация, спринт, квалификация и гонка.

Ссылки можно менять без пересборки приложения: **админка → «трансляции»**. Выбери этап, вставь полную ссылку Rutube или только id видео и нажми «сохранить». Приложение само достанет id из ссылки и будет обновлять плеер у всех через realtime.

Ссылки из кода остаются запасными. Их можно вписать в `season.ts`:

```ts
{
  round: 18,
  title: 'Гран-при США',
  start: '2026-10-25T14:00:00-05:00',
  practice1VideoId: 'сюда_id_из_ссылки_rutube',
  practice2VideoId: '...',
  practice3VideoId: '...',
  sprintQualyVideoId: '...',
  sprintVideoId: '...',
  qualyVideoId: '...',
  raceVideoId: '...',
}
```

Id — это часть ссылки `https://rutube.ru/video/<id>/`. Плеер собирается сам: `https://rutube.ru/play/embed/<id>`. Если в Supabase для этой сессии сохранена другая ссылка, она важнее кода.

> Время старта в календаре указано по местному времени трассы. Если дата/время сдвинутся, поправь `start` — таймер пересчитается.

## 7. Админка, баны и галочки

Администратором становится **первый зарегистрировавшийся на сервере**. В профиле у него появляется кнопка «админ-панель» и золотая плашка `ADMIN`.

В админке четыре вкладки:

- **люди** — выдать/снять галочку «проверенный» и забанить/разбанить. Забаненный не может войти, писать в чат и создавать объявления; его сообщения остаются видимыми.
- **объявления** — очередь проверки: одобрить, отклонить (объявление пропадает из ленты) или удалить.
- **трансляции** — выбрать этап и вставить ссылки Rutube на практики, спринт-квалификацию, спринт, квалификацию и гонку.
- **ИИ-модерация** — настройки модели.

Себя забанить нельзя, а галочку админ может выдать и себе.

Если нужно назначить второго админа, выполни в SQL Editor:

```sql
update public.profiles set is_admin = true where username = 'нужный_username';
```

## 8. Проверка объявлений

Перед публикацией объявление проходит проверку:

1. **Правила (работают всегда и без ключей).** Блокируют: стоп-слова (казино, ставки, наркотики, скам и т.п.), слишком короткое название, отсутствие города. Отправляют на проверку: ссылки и ники, номера телефонов, рекламные слова, капс, много восклицательных знаков, цена выше 20 000 ₽.
2. **ИИ (если включён).** Любая OpenAI-совместимая модель читает текст и возвращает `ok / review / blocked`. Подходит OpenRouter, Groq, локальная Ollama. Если модель недоступна — проверка откатывается к правилам и публикация не встаёт.

Результат виден автору: «проверено», «на проверке» (админ увидит в очереди) или «отклонено» с причиной.

> Ключ API хранится в Supabase (`ai_settings`). Прямого доступа к таблице нет: админ получает настройки через защищённую функцию. При запросе к модели ключ используется в браузере админа, поэтому не выдавай админку посторонним.

## 9. Интернет и офлайн

В шапке главной и на экране трансляции есть чип **онлайн / офлайн**, в профиле — тоже. Когда связь пропадает, сверху появляется красная плашка, а отправка сообщений и объявлений блокируется с понятным текстом. Состояние определяется браузером (`navigator.onLine` + события `online` / `offline`).

Это статус **своего** устройства. Читать данные без сети нельзя: они лежат на сервере. Уже загруженные экраны остаются на месте, но новые сообщения не придут, пока связь не вернётся.

## 10. Как выложить в интернет

### Netlify Drop

1. Собери проект: `npm run build`.
2. Открой https://app.netlify.com/drop и перетащи папку `dist`.
3. Получи ссылку вида `https://random-name.netlify.app`.

При сборке локально ключи из `.env` уже вшиты в файлы. Если собираешь на Netlify из репозитория — добавь `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в **Site settings → Environment variables**.

После публикации обязательно пропиши этот адрес в Supabase: **Authentication → URL Configuration → Site URL** и **Redirect URLs** (см. 1.2). Если хочешь, чтобы ссылки из писем всегда вели на сайт, добавь `VITE_SITE_URL=https://твой-сайт` в переменные окружения и пересобери проект.

### Vercel

1. Зарегистрируйся на vercel.com.
2. `npm i -g vercel`, затем в папке проекта: `vercel`.
3. Переменные окружения — в настройках проекта (`vercel.json` уже настроен).

### GitHub Pages

Роутинг сделан через hash (`/#/race`), поэтому работает на любом статическом хостинге без настройки редиректов.

> Rutube-плеер встраивается через iframe и требует интернета. Если сеть блокирует Rutube, остальное приложение продолжает работать.

## 12. Ограничения

- **Оплата** — просто отметка «билет куплен», платёжной системы нет.
- **Письма** — подтверждение и восстановление пароля требуют включённого **Confirm email**, настроенного SMTP и добавленных Redirect URLs (см. 1.2). Без SMTP письма могут не дойти или попасть в спам.
- **Android-ссылки из писем** — работают через `app.freedgrid.mobile://auth`; эта схема должна быть в Redirect URLs Supabase. В PWA и на сайте письма открывают обычный адрес сайта.
- **Виджеты** — только в Android APK, в PWA их нет. Данные появляются после первого открытия приложения; в профиле есть кнопка «обновить виджет».
- **Один админ по умолчанию** — остальных назначай SQL-запросом из раздела 7.
- **Голос** — mesh-схема и STUN без гарантии для всех мобильных операторов; для стабильности добавь TURN.
- **Модерация** — ИИ вызывается из браузера админа, потому что отдельная серверная функция не развёрнута. Ключ при этом не публичен.
